# План на старт разработки

Платформа автоматизации транспортных и экспедиторских компаний.  
Стек ориентир: **Go** (backend), **Vue 3 + TypeScript** (кабинет), PostgreSQL, Redis, S3-совместимое хранилище, очереди; ИИ — hybrid, чувствительное в контуре.

Команда на старте: техдир/backend lead, frontend, системный/бизнес-аналитик. DevOps / 1С / ИБ — точечно.

---

## Цель первых 12 недель

Пилот у одного клиента: реальные заявки и КП обрабатываются в системе людьми, а не в чате с нейросетью.

Метрики успеха пилота (зафиксировать на неделе 1–2):
- время от входящего КП/заявки до сравнимого вида в одном окне;
- доля полей, извлечённых ИИ без ручной правки;
- число заявок/КП, реально проведённых через систему за неделю пилота.

---

## Сроки (единый список)

- Неделя 1. Встречи с основателем и клиентами, карта процесса, сбор корпуса файлов, разбор наработок, черновик MVP, схема потоков данных и ИБ.
- Неделя 2. Утверждение scope и метрик, выбор размещения пилота, каркас Go + Vue + CI на stage, модель данных v0, логин и роли, регламент ИИ для команды.
- Неделя 3. Заявки со статусами, загрузка файлов, список и карточка заявки, словарь полей и статусов.
- Неделя 4. Контрагенты, входящие КП, связь с заявкой, карточка КП и таблица предложений, шаблон исходящего КП.
- Неделя 5. Очередь задач, приоритет по правилам, журнал действий, экран «мои задачи» и дашборд руководителя v0. Ручной контур готов к демо без ИИ.
- Неделя 6. Пайплайн разбора файла через очередь и модель в контуре: черновик полей с уверенностью и источником, без записи сразу в боевые поля.
- Неделя 7. Экран подтверждения и правки извлечения, валидация чисел и дат кодом, метрики качества на корпусе клиента.
- Неделя 8. Окно сравнения предложений, выбор перевозчика, исходящее КП из шаблона, вход из Telegram или почты.
- Неделя 9. Выкат на пилот, обучение 2–3 сотрудников, канал поддержки, список блокеров.
- Неделя 10. Правки по боли пилота, только критичные интеграции (1С/ATI — если без них нельзя работать).
- Неделя 11. Бэкапы с проверкой восстановления, MFA админам, запрет выхода на зарубежные ИИ из prod, черновик пакета для СБ.
- Неделя 12. Замер метрик, отчёт основателю, решение по scope и бюджету на следующие 3 месяца.

Итого до пилота в работе: 12 недель. Дальше план v1 отдельно по фактам пилота.

---

## Что не делаем до конца пилота

- Все тендерные площадки и «программа для каждого отдела»
- Нативное мобильное приложение
- Полный ЭДО и идеальный голосовой ввод
- Автоматическое проведение сделок без подтверждения человека
- Микросервисный зоопарк и досрочный K8s «для красоты»
- Копии репозитория под каждого клиента

---

## Ритуалы с первой недели

- Ежедневный короткий синк команды (15 мин)
- Раз в неделю демо основателю (и клиенту с недели 6–7)
- Один backlog: product / tech / ib; в спринт только то, что двигает пилот
- Definition of Done: на stage, есть приёмка аналитика, для ИИ-полей — сценарий с файлом из корпуса

---

## Риски на старте и как гасим

- Scope расползается → одна страница MVP, всё новое в backlog после пилота.
- ИИ врёт в ставках → только черновик и подтверждение человека.
- Нет живых файлов → без корпуса не начинаем ИИ-разбор.
- 1С/ATI внезапно обязательны → решение на неделе 2; если да, подрядчик с недели 8–9.
- СБ клиента жёстче ожиданий → схема контуров на неделе 1, выделенный инстанс закладываем заранее.

---

## Первые конкретные deliverables (checklist)

- [ ] Scope MVP на 1 странице, подписан основателем  
- [ ] Корпус файлов клиента  
- [ ] Stage: Go API + Vue + PostgreSQL + загрузка файла  
- [ ] Ручной путь заявки и КП  
- [ ] ИИ-черновик извлечения с подтверждением  
- [ ] Сравнение + исходящее КП  
- [ ] Один канал входа (Telegram или почта)  
- [ ] Дашборд руководителя v0  
- [ ] Журнал действий и роли  
- [ ] Пилот на 2–3 пользователях, отчёт по метрикам  

После этого — план на v1 (тендеры deeper, интеграции, тираж, усиление ИБ) отдельно, уже по фактам пилота.
