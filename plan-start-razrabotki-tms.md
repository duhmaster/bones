# План на старт разработки

Платформа автоматизации транспортных и экспедиторских компаний.  
Стек ориентир: **Go** (backend), **Vue 3 + TypeScript** (кабинет), PostgreSQL, Redis, S3-совместимое хранилище, очереди; ИИ — hybrid, чувствительное в контуре.

Команда на старте: техдир/backend lead, frontend, системный/бизнес-аналитик. DevOps / 1С / ИБ — точечно.

---

## Цель первых 12 недель

Пилот у одного клиента: реальные заявки и КП обрабатываются в системе людьми, а не в чате с нейросетью.

Метрики успеха пилота (зафиксировать на неделе 1–2):
- время от входящего КП/заявки до сравнимого вида в одном окне;
- доля полей, извлечённых ИИ без ручной правки;
- число заявок/КП, реально проведённых через систему за неделю пилота.

---

## Этап 0. Разведка и каркас (недели 1–2)

### Неделя 1

| Что | Кто | Результат |
|-----|-----|-----------|
| Встречи с основателем и 1–2 клиентами, разбор процесса «заявка → КП → перевозка» | техдир + аналитик | карта процесса, боли, что измеряем |
| Сбор 20–50 реальных файлов (PDF, Excel, фото, переписки) | аналитик | корпус для разбора и приёмки |
| Инвентаризация наработок: что живое, что слайд | техдир | список take / rework / rewrite |
| Черновик MVP: что входит, что сознательно нет | все | одностраничный scope |
| Рамка данных и ИБ: классы данных, контур, запрет зарубежных ИИ в prod | техдир | схема потоков на 1 страницу |

### Неделя 2

| Что | Кто | Результат |
|-----|-----|-----------|
| Утверждение scope MVP и метрик с основателем | техдир | go / no-go на разработку |
| Выбор размещения пилота (РФ-облако / выделенный контур) | техдир | решение + черновик сметы инфры |
| Каркас репозиториев: Go API, Vue кабинет, CI на lint/test/build | техдир + frontend | пустые сервисы деплоятся на stage |
| Модель данных v0: заявка, контрагент, КП, документ, пользователь, роль, аудит | техдир | миграции PostgreSQL |
| Роли и логин (минимальный RBAC) | техдир + frontend | вход в пустой кабинет |
| Регламент работы с ИИ у команды (бой vs разработка кода) | техдир | короткие правила |

**Выход этапа 0:** согласованный MVP, каркас в stage, понятно что берём из наработок, есть корпус файлов клиента.

## Этап 1. Скелет продукта (недели 3–5)

Фокус: человек может завести заявку/КП руками и пройти базовый путь без ИИ.

| Неделя | Backend (Go) | Frontend | Аналитик |
|--------|--------------|----------|----------|
| 3 | CRUD заявки, статусы, загрузка файла в хранилище, метаданные документа | Список/карточка заявки, загрузка файла | Поля заявки и КП, обязательность, словарь статусов |
| 4 | Контрагенты, входящее КП как сущность, связь с заявкой | Карточка КП, таблица предложений | Шаблоны исходящего КП (поля) |
| 5 | Очередь задач сотрудника, простой приоритет правилами, журнал действий | «Мои задачи», фильтры, экран руководителя v0 | Правила приоритета v0, сценарии приёмки |

**Выход:** ручной контур работает end-to-end на stage; можно демо без ИИ.

---

## Этап 2. ИИ-разбор и сравнение (недели 6–8)

Фокус: ускорение входа, не автопилот.

| Неделя | Что делаем |
|--------|------------|
| 6 | Пайплайн: файл → очередь → вызов модели в контуре → черновик полей с confidence и цитатой-источником. ИИ не пишет в боевые поля. |
| 7 | UI подтверждения/правки извлечения; валидация чисел и дат кодом; метрики % без правки. Разбор на корпусе клиента. |
| 8 | Окно сравнения предложений; выбор перевозчика; генерация исходящего КП из шаблона (данные уже подтверждённые). Вход из Telegram и/или почты (один канал обязательно, второй по возможности). |

**Выход:** логист разбирает реальные КП быстрее, чем в Excel/чатах; есть цифры по качеству извлечения.

## Этап 3. Пилот и упрочнение (недели 9–12)

| Неделя | Что делаем |
|--------|------------|
| 9 | Выкат на контур пилота; обучение 2–3 сотрудников; канал поддержки; список блокеров |
| 10 | Правки по боли пилота; добор только критичных интеграций (1С/ATI — если без них пилот мёртв) |
| 11 | ИБ-минимум: бэкапы с проверкой restore, MFA админам, сетевой запрет на зарубежные ИИ из prod, черновик пакета для СБ |
| 12 | Замер метрик; отчёт основателю: что взлетело, что нет, budget/scope на следующие 3 месяца |

**Выход:** система используется на реальных задачах; решение тиражировать или сузить.

---

## Что не делаем до конца пилота

- Все тендерные площадки и «программа для каждого отдела»
- Нативное мобильное приложение
- Полный ЭДО и идеальный голосовой ввод
- Автоматическое проведение сделок без подтверждения человека
- Микросервисный зоопарк и досрочный K8s «для красоты»
- Копии репозитория под каждого клиента

---

## Ритуалы с первой недели

- Ежедневный короткий синк команды (15 мин)
- Раз в неделю демо основателю (и клиенту с недели 6–7)
- Один backlog: product / tech / ib; в спринт только то, что двигает пилот
- Definition of Done: на stage, есть приёмка аналитика, для ИИ-полей — сценарий с файлом из корпуса

---

## Риски на старте и как гасим

| Риск | Что делаем сразу |
|------|------------------|
| Scope расползается | Одна страница MVP, всё новое — в backlog после пилота |
| ИИ врёт в ставках | Только черновик + подтверждение человека |
| Нет доступа к живым файлам | Без корпуса не начинаем этап 2 |
| 1С/ATI внезапно обязательны | Решение на неделе 2; если да — подрядчик в плане с недели 8–9 |
| СБ клиента жёстче ожиданий | Схема контуров на неделе 1; выделенный инстанс закладываем заранее |

---

## Первые конкретные deliverables (checklist)

- [ ] Scope MVP на 1 странице, подписан основателем  
- [ ] Корпус файлов клиента  
- [ ] Stage: Go API + Vue + PostgreSQL + загрузка файла  
- [ ] Ручной путь заявки и КП  
- [ ] ИИ-черновик извлечения с подтверждением  
- [ ] Сравнение + исходящее КП  
- [ ] Один канал входа (Telegram или почта)  
- [ ] Дашборд руководителя v0  
- [ ] Журнал действий и роли  
- [ ] Пилот на 2–3 пользователях, отчёт по метрикам  

После этого — план на v1 (тендеры deeper, интеграции, тираж, усиление ИБ) отдельно, уже по фактам пилота.
