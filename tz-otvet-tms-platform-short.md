# Ответ на ТЗ (кратко)

Здравствуйте. Ниже — как бы я строил продукт: коротко и по пунктам.

## 1. Архитектура

Это учётная и операционная система экспедитора, не чат с нейросетью. ИИ только на разборе хаотичного входа. Статусы, деньги, права, журналы — обычный код.

**Стек, который выберу сам:**
- Frontend: Vue 3 + TypeScript (кабинет логиста, тендерщика, руководителя). На старте адаптив + Telegram как канал, без нативной мобилки.
- Backend: **Go**, модульный монолит (API + домен + воркеры в одном репо). Почему Go: один бинарник, стабильность под пиками, простой деплой в облаке и on-prem, предсказуемые интеграции и очереди.
- БД: PostgreSQL + Redis; файлы в S3-совместимом хранилище; очереди RabbitMQ или Redis Streams.
- Инфра: Docker, РФ-облако; K8s когда появится второй контур и DevOps.

**Модули:** заявки, контрагенты/перевозчики, подбор транспорта, расчёт и КП, тендеры (assist), документы, задачи, отчёты, интеграции, роли и аудит.

**MVP (пилот у 1 клиента):** вход из файла/Telegram/почты → извлечение → правка человеком → сравнение КП → исходящее КП → очередь задач → простой дашборд → роли и журнал. Не в MVP: все площадки, полный ЭДО, голос «на отлично», автопилот по деньгам без человека.

## 2. ИИ

Выбор: **Hybrid**, чувствительное — в контуре.

- Local / сервер в контуре: разбор заявок, КП, договоров, тендеров с реквизитами и ПДн.
- Российский cloud (GigaChat, YandexGPT и т.п.): только нечувствительные сценарии и только если ИБ заказчика разрешил.
- Без ИИ: маржа, статусы, шаблоны КП, права, поиск по API, валидация полей.

Зарубежные публичные API для боевых документов заказчика не использую.

**Антигаллюцинации:** ИИ пишет в черновик, не в боевые поля; у поля есть источник и confidence; ниже порога — обязательная правка человека; жёсткая схема полей; цифры дополнительно валидирует код; метрики % полей без правки.

## 3. ИБ и данные

Данные остаются в согласованном контуре: приложение + БД + файлы + local LLM вместе; наружу только то, что явно разрешено.

**Размещение:** российское облако (основной путь); выделенный VPC/сервер под клиента; on-prem у заказчика при требовании СБ. Для госсектора — тот же код на выделенном инстансе, не форк.

**Технически:** TLS; шифрование дисков и бакетов; RBAC + MFA админам; журнал кто смотрел/правил/выгружал; бэкапы с проверкой restore; секреты не в git; из prod нет выхода на зарубежные ИИ; единый AI Gateway в коде; маскирование ПДн если когда-либо уходит в cloud RU.

**Для СБ заказчика:** схема потоков данных, список подрядчиков, роли, логи, бэкапы, инцидент-регламент, базовый security-scan. С юристом: ПДн, договоры облака/ИИ (без обучения на ваших данных), сроки хранения, ответственность за ошибку ИИ в ставках (поэтому подтверждение человеком обязательно).

## 4. Сроки, деньги, команда, ИИ-агенты

| | Оценка |
|--|--------|
| Разведка и каркас | 2–3 недели |
| MVP | ещё 2,5–4 месяца |
| Полноценная v1 | ещё 4–6 месяцев после MVP |
| Бюджет MVP | 5–9 млн ₽ (ориентир 6–8) |
| До v1 | ещё 6–12 млн ₽ |
| Облако + хранение на пилоте | ~30–80 тыс. ₽/мес |
| GPU под local LLM | ~80–250+ тыс. ₽/мес или сервер у клиента |
| Поддержка после запуска | ~0,4–1 млн ₽/мес |

**Команда на MVP:** я (Go/архитектура/лид), frontend, системный/бизнес-аналитик; DevOps, 1С, ИБ — точечно снаружи.

**ИИ-агентам под контролем:** каркас CRUD, формы, тесты, черновики парсеров и промптов.  
**Живым специалистам:** домен, границы ИИ, изоляция тенантов, интеграции, маршрут данных.  
**Не доверяю агентам:** финальные права и аудит, правила утечки во внешний ИИ, юридически значимые тексты без шаблона, «сами сдайте СБ», запись в прод без человека на деньгах.

## От дня 1 до запуска

Недели 1–2: клиенты и процессы, разбор наработок, scope MVP и метрики, схема контуров для ИБ, каркас на Go.  
Недели 3–8: кабинет логиста end-to-end на реальных файлах, еженедельное демо.  
Недели 9–12: пилот, обучение, замеры, добор интеграций только если без них нельзя.  
Дальше: стабилизация и тираж конфигом, не копипастом репозитория.

Готов сузить оценку после просмотра ваших наработок и требований пилотного клиента.
